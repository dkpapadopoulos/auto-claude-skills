# Test-suite discipline

Path-scoped rule, split out of the repo-root `CLAUDE.md` Gotchas section so it
loads only when you touch the files it governs. History moved out of these bullets, with
the test, if any, that now guards it, is in `docs/history/rules-test-suite.md` (loaded by nothing).

- **A capped `gh` query is byte-indistinguishable from a complete one (#209).** `skills/improvement-miner/scripts/mine-evidence.sh` checks each capped intake (eval reports, the run ledger) with `assert_not_truncated <json> <limit> <what>`, which fails loud (exit 5) on `length >= limit`: reaching the cap exactly counts as truncation, because the client cannot tell the two apart. Keep each limit a VARIABLE shared with its query, so the check cannot drift from it. The guard counts only an ARRAY (`jq length` also counts object keys and string characters), and an absent limit returns rather than defaulting to `0`, which would compare `0 >= 0` and stop every run. The run ledger is the kill-math source of truth and grows one issue per run, so any fixed cap is a forward-dated hard stop; its remedy is `IMPROVEMENT_MINER_LEDGER_LIMIT`, because in a target repo the script is the versioned plugin cache and an edit there is undone by the next update. Regression: `tests/test-improvement-miner.sh`.

- **A test file's bare call list is unchecked in BOTH directions unless something checks it.** An invoked-but-undefined test prints `command not found` and the file still reports "All tests passed"; a defined-but-never-invoked test never runs and nothing says so. `tests/test-suite-wiring.sh` (#271) sweeps every `tests/test-*.sh` that defines a `test_*()` function through `assert_test_functions_wired` (`tests/test-helpers.sh`), and fails any file whose direct `TESTS_PASSED`/`TESTS_FAILED` bumps outnumber its `TESTS_RUN` bumps: record verdicts with `_record_pass`/`_record_fail`, or bump `TESTS_RUN` with every verdict. The sweep sees only assertions inside an invoked `test_*` function; a file that asserts mostly at top level fails the mixed-shape cell until you read it and add it to `_EXPECTED_MIXED_SHAPE`. Any guard that compares two sets must check both differences (a one-directional guard misses the one that silently deletes coverage) and needs a floor: with zero matches (a bad path, CRLF, a changed idiom) every comparison holds and it reports a pass having checked nothing.

- `tests/test-regex-fixtures.sh` only checks fixtures that EXIST — `tests/test-fixture-coverage.sh` enforces that every owned, trigger-routed skill HAS one (with >=1 MATCH + >=1 verbatim-borrowed NO_MATCH decoy). `security-scanner` (composition-only, empty triggers) is exempt.

- `tests/test-skill-content-coverage.sh` is the parallel gate for content-assertion tests: every owned, trigger-routed skill must be referenced by some `tests/*.sh` (detected by the string `skills/<name>/`, NOT by filename — content tests have no naming convention: `product-discovery`→`test-discovery-content.sh`, `runtime-validation`→`test-validation-skill-content.sh`). Same population/exemptions as the fixture gate. **Mock-path exclusion:** references under `.claude/skills/<name>/` do NOT count — registry/discovery tests (e.g. `test-registry.sh`) build fake skill trees at `${HOME}/.claude/skills/<name>/` using real skill names but assert nothing about the real `SKILL.md`; counting them would false-pass (this bit `agent-team-execution` in review). Presence-not-quality is the deliberate deterministic bar (an empty test would pass) — quality stays human-review, like `test-skill-anatomy.sh`'s heading check.

- **Review adjudication (#205): the procedure is `skills/agent-team-review/SKILL.md` §4a and §5; change it there.** That is what a review lead reads: change one causal variable and build a pair that could disagree; call a non-flip "false" only after a COMPARABLE positive control flips in the same harness; an unobtainable pair is `could-not-reproduce`, keeps its severity, and constrains the verdict; reproduce in a detached worktree carrying `git diff HEAD` plus untracked files. Keep §4a's scope exception: it binds only findings making an *experimentally decidable causal claim*, never `security`/`governance` findings blocking on the structural criterion the finding contract already allows; demanding a runnable pair for those would quietly repeal that exception. `tests/test-review-adjudication.sh` pins most §4a clauses (not the `warning`-severity verdict arm, reaping the worktree, or the default-config confounder) and the seeded corpus `tests/fixtures/agent-team-review/adjudication/seeded-findings.md` (3 real-but-confounded, 3 false, each measured against the real guard). Nothing scores that corpus and it is memorisable, so it is a set of worked examples, never a certification. Two lessons from that test apply to any test you write. A gate driven by a needle fixture needs a second authority (anchors hardcoded in the test) and a count floor, or deleting a needle silently deletes its own assertion. And every assertion loop must run in the current shell — fed by a redirect (heredoc, file, process substitution) or a glob `for`, never a pipe: a piped loop runs `_record_pass`/`_record_fail` in a subshell, and a clause mutated out of the skill printed FAIL while the summary still read 9/9 and exited 0.


- **The 150,000-char instruction-file limit is a TOTAL across files, not a per-file cap, and it warns about context cost — nothing is truncated.** A rule file with `paths:` frontmatter loads on demand and is outside the session-start total; an UNSCOPED rule loads at launch and counts. LEG 7 of `tests/test-claude-md-rule-split.sh` asserts the session-start total against 150,000 and two per-file rules (the docs' 200-line target, documented for CLAUDE.md only and applied here to every file, and the documented 4 MiB skip), and RATCHETS the all-files byte total (`_COMBINED_BASELINE`): growth and an unbanked shrink both fail, and the true percentage is printed every run. Its header holds the measurements and the reasoning. Do not replace the ratchet with the real limit: the all-files total is already over 150,000, and `.verify.yml` makes the whole suite the push gate, so one red cell denies every routing push repo-wide. Move the baseline to the measured total in the same commit as any edit to `CLAUDE.md` or `.claude/rules/*.md`, and say why (same convention as `INCIDENT_SKILL_WORD_BASELINE`). **The transferable lesson:** a per-file budget against a combined limit is the wrong SHAPE, not the wrong number — 130k across 8 files permits 6.9x the limit, green throughout.
