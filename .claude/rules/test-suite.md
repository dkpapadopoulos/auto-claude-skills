# Test-suite discipline

Path-scoped rule, split out of the repo-root `CLAUDE.md` Gotchas section so it
loads only when you touch the files it governs. Every bullet is verbatim.

- **A capped `gh` query is byte-indistinguishable from a complete one (#209), and an undefined test function is silent.** `skills/improvement-miner/scripts/mine-evidence.sh` intakes two capped lists — eval reports at `--limit 50`, the run ledger at `--limit 200` — and neither noticed when the cap was REACHED, so the miner would quietly mine a partial corpus. The ledger is the severe one: it is the **kill-math source of truth**, so a silently dropped run moves the approved/presented counters that decide whether the skill decommissions itself. `assert_not_truncated <json> <limit> <what>` now fails loud on `length >= limit`, matching this script's existing posture that an incomplete bundle must never look like a complete one; the limits are VARIABLES so the check cannot drift from the query it guards, it counts only an ARRAY (`jq length` also counts object keys and string characters), and an absent limit returns rather than defaulting to `0` — which would have compared `0 >= 0` and bricked every run. **The ledger cap is a FORWARD-DATED HARD STOP**: the ledger grows one issue per run and is never pruned, so at run 200 both `bundle` and `dedup` would exit 5 permanently — and the obvious remedy ("raise the limit in mine-evidence.sh") is unapplicable in a target repo, where that file is the versioned plugin cache and editing it is undone by the next update and trips the drift canary. Hence `IMPROVEMENT_MINER_LEDGER_LIMIT`. Reaching the cap exactly counts as truncation because the two cases are indistinguishable from the client. **No live instance** — the eval query is SEARCH-scoped (`"Behavioral eval regression" in:title`, 1 hit today, which is why #94 surfaces at all despite 268 issues) and the ledger holds 3 of 200 — which is the reason it needed a test rather than a note to look again later. PAIRED, found while writing those cells and worth more than the fix: **a test file that ends in a BARE LIST OF FUNCTION CALLS is unchecked in BOTH directions, and each direction fails silently.** *Invoked but not defined*: bash prints `command not found`, the file keeps going, and `print_summary` still reports "All tests passed" with exit 0 — measured, four undefined names gave **123/123 green**. *Defined but not invoked*: the test simply never runs and nothing says so — **live instance: `test_no_stderr_without_explain` (`tests/test-routing.sh:3404`) is defined and invoked nowhere, so it has never run.** The second direction is the one that quietly deletes coverage, and it is the one a one-directional guard misses. The run count is the only tell, and the size of the drop is test-specific (it equals that test's assertion count), so do not memorise a figure. `assert_test_functions_wired` (in `tests/test-helpers.sh`, so other files can adopt it) compares the DEFINED and INVOKED sets both ways **and carries a floor**: with no needles — an unresolvable path, a CRLF checkout, an indented call list — both sets are empty, every comparison trivially holds, and the guard would report a pass having checked nothing. **20 files have this shape and only one is guarded so far**; `tests/test-routing.sh` alone has 221 bare calls. Adjacent, pre-existing, same theme: `test-routing.sh` reports `Tests run: 496 / Tests passed: 500` — more passes than runs, because some arms bump `TESTS_PASSED` without `TESTS_RUN`. That string is also what a previous session misread as a suite result, so it is worth knowing it is genuinely inconsistent rather than merely confusable. Regression: `tests/test-improvement-miner.sh` (both guards mutation-verified; removing either truncation call fails exactly its own two cells and not the other's).

- `tests/test-regex-fixtures.sh` only checks fixtures that EXIST — `tests/test-fixture-coverage.sh` enforces that every owned, trigger-routed skill HAS one (with >=1 MATCH + >=1 verbatim-borrowed NO_MATCH decoy). `security-scanner` (composition-only, empty triggers) is exempt.

- `tests/test-skill-content-coverage.sh` is the parallel gate for content-assertion tests: every owned, trigger-routed skill must be referenced by some `tests/*.sh` (detected by the string `skills/<name>/`, NOT by filename — content tests have no naming convention: `product-discovery`→`test-discovery-content.sh`, `runtime-validation`→`test-validation-skill-content.sh`). Same population/exemptions as the fixture gate. **Mock-path exclusion:** references under `.claude/skills/<name>/` do NOT count — registry/discovery tests (e.g. `test-registry.sh`) build fake skill trees at `${HOME}/.claude/skills/<name>/` using real skill names but assert nothing about the real `SKILL.md`; counting them would false-pass (this bit `agent-team-execution` in review). Presence-not-quality is the deliberate deterministic bar (an empty test would pass) — quality stays human-review, like `test-skill-anatomy.sh`'s heading check.

- **A review lead must isolate ONE fault before deciding a finding (#205).** `skills/agent-team-review/SKILL.md` §4a: reproduce with the claimed cause present and absent, everything else fixed, and require the two runs to **disagree**. Binds in BOTH directions — a finding "that failed to reproduce" is not refuted without the pair (say "failed to trigger", not "refuted"), and one accepted without a flipping pair is a guess with a file:line attached whose test asserts nothing. The mechanism: **an upstream fail-closed gate masks a downstream fall-open one**, so until every OTHER gate is independently satisfied the variable under test contributes nothing observable. Two confounder shapes are both live and only the first is obvious: a second injected fault, and **the DEFAULT CONFIG** — measured, `phase-evidence.sh` removed under `phase_enforcement.outbound: deny` flips deny→allow, while under the default `warn` both runs allow, so one reproduction on an untouched machine refutes a true finding. Unobtainable pair ⇒ `could-not-reproduce` + reason, severity PRESERVED, routed to the user as open (never a silent demotion). Reproduction runs in a **detached worktree** — adjudication injects faults on purpose, and doing that in the shared tree corrupts concurrent sessions and (per #219) measures a tree nobody is pushing. Pinned corpus: `tests/fixtures/agent-team-review/adjudication/seeded-findings.md`, 3 real-but-confounded + 3 false, **every cell measured against the real guard** (`git-command.sh` and `phase-evidence.sh` flip; `pr-diff.sh`, `implement-shadow.sh`, `push-gate-capture.sh` do not — "sourced by the guard" is not "gates"). **SCOPE, and getting it wrong repeals an existing rule:** §4a binds only on findings making an *experimentally decidable causal claim*, and explicitly NOT on `security`/`governance` findings blocking on the structural criterion the finding contract already allows — demanding a runnable pair for "this removes a safety constraint" would quietly delete that exception (caught in review). The oracle is whatever the finding predicts (a field, an exit code, an artifact), named BEFORE the run, not necessarily allow/deny. **A non-flipping pair is NOT proof of falsity** — three explanations (claim false / intervention incomplete / preconditions unmet) and the lead must name which; calling the last two "refuted" is the original mistake wearing a control. **PAIRED, and the first cut contradicted itself here:** a non-flip decides "false" ONLY once the other two are ruled out, and the way to rule them out is a **POSITIVE CONTROL** — a variable known to flip, run in the SAME harness. Without that, "it did not reproduce" and "it did not reproduce in a harness that provably reproduces something else" are indistinguishable, and only the second is evidence. That is precisely what makes the seeded set decidable: REAL-1 flips under the identical subject/control/preconditions the three FALSE cells use, so it IS their positive control. State it whenever you reject a finding. **An OPEN (`could-not-reproduce`) finding constrains the VERDICT, it is not neutral**: blocking-severity open ⇒ never `clean`/`suggestions_only` (route `blocking_issues`, name it, let the user decide explicitly); warning-severity open ⇒ `suggestions_only` at most. "We could not test it" is the most dangerous disposition because it reads as harmless. The finding contract gains an `Oracle:` line so the lead does not invent the oracle after seeing the result. **The reproduction worktree's uncommitted delta is `git diff HEAD`, NOT `git diff <base_sha>`** — base..head is already IN the checked-out sha, so the latter re-applies committed changes on top of themselves; untracked files are in neither and must be copied explicitly. The reproduction worktree must carry the REVIEWED change: `git worktree add --detach <wt> <head_sha>` adjudicates the PARENT state for uncommitted work, so apply the diff explicitly, and reap the worktree. Bar is >=5/6 AND REAL-1 classified REAL: that clause is not redundant, REAL-1 is the one whose naive reproduction argues for the wrong answer — but **the bar is prose that nothing enforces, and the set is memorisable** (every REAL cell is a `_GATE_ENFORCE_LIBS` member, every FALSE cell advisory/diagnostic, so a keyword rule scores 6/6 constructing no control), so it is a set of worked examples, never a certification. Gate: `tests/test-review-adjudication.sh` — two authorities (fixture needles + anchors hardcoded in the test) plus a count floor, mutation-verified 3/3. PAIRED: its loops are **heredoc-fed, never piped** — the first cut piped them, so `_record_pass`/`_record_fail` ran in a subshell, and mutating a clause out of SKILL.md printed one FAIL while the summary still read 9/9 and exited 0. Any assertion loop in a test file must run in the current shell.


- **The 150,000-char instruction-file limit is a TOTAL across files, not a per-file cap, and it warns about CONTEXT COST — nothing is ever truncated.** Product string, anthropics/claude-code#96506: `N instruction files add up to 192.2k chars, over the 150.0k-char total limit ... /memory to free up context`. A rule file WITH `paths:` frontmatter loads on demand, not at launch, so it is NOT in the session-start total (measured via an `InstructionsLoaded` hook: `load_reason=path_glob_match` for rules vs `session_start` for CLAUDE.md) — which is why the split WORKED: `63564586` was 154,492 chars at session start (102%, genuinely over), `089701b8` 23,083 (15%), today 25,140 (17%). What grows instead is the WORST CASE, every rule loaded in one session, now ~113% — real, but a cost paid on demand. An UNSCOPED rule file does load at launch and does count. The docs quantify only "target under 200 lines per CLAUDE.md file" and a 4 MiB hard SKIP (a larger file does not load at all); the combined limit's existence is documented, its value is not. LEG 7 of `tests/test-claude-md-rule-split.sh` asserts those two per-file rules and RATCHETS the combined byte total, failing on growth and on an unbanked shrink, printing the true percentage every run. A ratchet rather than the real limit because asserting 150,000 goes red today and `.verify.yml` makes the whole suite the push gate — one red cell denies every routing push repo-wide. Raising the baseline is allowed but never silent: same convention as `INCIDENT_SKILL_WORD_BASELINE`, raise it in the same commit and say why. **The transferable lesson:** a per-file budget against a combined limit is the wrong SHAPE, not the wrong number — 130k across 8 files permits 6.9x the limit, green throughout.
