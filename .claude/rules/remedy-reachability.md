# Gate remedies an agent can actually execute

Path-scoped rule, split out of the repo-root `CLAUDE.md` Gotchas section so it
loads only when you touch the files it governs. History moved out of these bullets, with
the test, if any, that now guards it, is in `docs/history/rules-remedy-reachability.md` (loaded by nothing).

- **A remedy an agent cannot execute is not a remedy (#248): it must work from an EXTERNAL repo, in zsh, with `CLAUDE_PLUGIN_ROOT` unset.** `CLAUDE_PLUGIN_ROOT` is set in the hook process but UNSET in the model's Bash turn, and `$(git rev-parse --show-toplevel)/hooks/lib/phase-attest.sh` resolves to the USER's repo root, which has no `hooks/lib/` — so in an external repo the pair `${CLAUDE_PLUGIN_ROOT:-$(git rev-parse --show-toplevel)}/…` resolves to nothing and `phase_attest` is `not found`. **Copying a sibling's source line therefore fixes nothing** — that is the trap, because the obvious diff looks like it closes the issue. A hook that holds the path prints it: `hooks/openspec-guard.sh` already resolves `_PLUGIN_ROOT` to an absolute path into the versioned plugin cache, so `_attest_remedy <step>` prints THAT, and `hooks/skill-gate.sh` renders the same shape; a hook telling an agent how to find the hook's own libs, while holding the path, is the avoidable indirection. **This is load-bearing for the IMPLEMENT deny-flip pre-registration, not tidiness:** its decision rule classifies a deny resolved by one truthful attestation as a `true_catch`, which assumes attesting was possible — reachability was the untested premise under that classification. PAIRED: **the remedy is executed by the MODEL, so it must work in zsh as well as bash** — `phase-attest.sh` locates its sibling via `${BASH_SOURCE:-}`, which is empty in zsh, so a remedy verified only under bash can be broken for every real user. Every rendering of a remedy must change together and must ESCAPE (today the `phase_attest` remedy has four: `_attest_remedy`, the skill-gate inline, and the two config preconditions in the population bullet below): asymmetry among paired sites is the thing to look for when one of them is patched by hand. Regression: `tests/test-attest-remedy-reachable.sh` — it **executes** each shipped remedy in a scratch external git repo with `CLAUDE_PLUGIN_ROOT` unset, under BOTH shells, and asserts `phase_attest` becomes callable; a string assertion would have passed on the broken version, which contained both `phase_attest` and a `source` line. It carries the red control that the pre-fix idiom is UNREACHABLE in both shells (without it, "the new remedy works" does not establish the old one failed), renders the skill-gate remedy by driving a REAL deny rather than reading the source string, lints **every** `hooks/*.sh` for a message naming `phase_attest` without saying where it lives (a lint over a hardcoded file list missed a site that already existed), and ANNOUNCES a skipped zsh leg rather than silently `continue`-ing, since zsh carries the headline claim.

- **A remedy rendered as a command to PASTE is single-quoted and escaped, and a test of its escaping lifts the hook's own lines.** Double quoting is not inert: measured, a plugin path of `/a$(touch /tmp/PWN)b` created the file in both bash and zsh on paste, and a path containing `"` was a syntax error. Escape `'` as `'\''`; inside double quotes `\'` is NOT an escape (backslash + quote), and a replacement built on it emitted `a\'\\'\'b`, which breaks the whole pasted line and is worse than a missing path. An install path containing `'` must still yield a parseable remedy — `hooks/skill-gate.sh` once embedded the path in literal single quotes with no escaping while its siblings escaped. This property is NEW with #248: the text it replaced named `$CLAUDE_PLUGIN_ROOT` as a *variable*, which was merely unset — broken, but harmless. A render helper that HAND-COPIES the hook's escaping only agrees with itself (mutating the hook left every escaping cell green), so lift the hook's own lines with `sed`.

- **Config text that reaches a prompt names a plugin file as `{{PLUGIN_ROOT}}/…`, which `hooks/skill-activation-hook.sh` substitutes, and the population is ANY text that reaches a prompt — never a list of fields.** A `precondition` is rendered verbatim, two of them name `phase_attest` (`executing-plans`' own, and `brainstorming`'s, which attests `agent-safety-review`), and the `executing-plans` one reaches EVERY IMPLEMENT-phase prompt in EVERY repo, i.e. earlier and far more often than the push-gate advisory. An enumeration of those fields missed a surface three times running: after the `precondition` strings came the `methodology_hints[].hint` field (read by a different loop, so "the renderer substitutes" was never true of the renderer), then `phase_compositions[*].hints[].text` (rendered verbatim by the `HINT:` branch that accumulates `COMPOSITION_HINTS`), then, together, the `spec-driven` preset's REWRITE of that field in `session-start-hook.sh` (fixing the configs alone leaves every spec-driven repo broken, including this one) and the INTENT EXTRACTION directive hardcoded into `SKILL_LINES`, which no config lint can reach. An enumeration scoped to named fields is SATISFIED by the next surface added and missed, so count the FIELDS that reach a prompt, not the messages you remember fixing; state a lint's POPULATION, because it is a claim about scope; and lint bare paths as well as backticked ones (`docs/plans/` excluded — that is the user's scratch dir). Every one of these hid for the same reason: the paths resolve in THIS repo, where plugin root == project root. Name code by symbol, never by line number: a pointer to that accumulator was wrong when written and the code has moved twice since. Regression: `tests/test-composition-hint-plugin-root.sh`, which renders through the REAL hook from an external repo under the default AND `spec-driven` presets, opens the path it named with `CLAUDE_PLUGIN_ROOT` unset, lifts BOTH expander branches out of the hook with `sed` and executes them against a root containing a quote AND a space, and carries a mutation cell that restores the pre-fix line SURGICALLY, because deleting every line naming the function takes its definition too and yields an empty render, which is a DIFFERENT fault and would pass a sloppy cell for the wrong reason.

- **Text `hooks/skill-activation-hook.sh` renders is not the only place a plugin path lives: `skills/*/SKILL.md` is a different class.** Nothing renders a SKILL.md — the Skill tool hands it to the model as-is — so there is no substitution pass to hook into, and `{{PLUGIN_ROOT}}` must NOT be copied there (the literal would reach the reader, strictly worse than the pair, which at least expands to something). Those files write `<PLUGIN_ROOT>/…` and `session-start-hook.sh` injects the absolute plugin root to substitute for it (issue #311, closed by PR #314; regression: `tests/test-skill-plugin-root-reachable.sh`). The two classes meet: a hint can hand the model a correct absolute path and route it into `Skill(…)`, whose body hands back a broken one for the identical command, which `skills/product-discovery/SKILL.md` once did for `set-discovery-path`.

- **The quoting is DELIBERATELY asymmetric and both halves are pinned: do not "make them consistent".** A precondition IS a pasted shell command, so it stays single-quoted and escaped; a hint NAMES a file to read, and shell quotes handed to a Read tool are literal characters that make the path unopenable, so hint paths are emitted BARE (a space survives because backticks delimit the span). `phase_compositions[*].hints[].text` carries BOTH consumer kinds, so the expander dispatches on how the text quotes its own placeholder rather than on the field — do not collapse that into one treatment. The `spec-driven` preset's copy lives inside a SINGLE-QUOTED shell string wrapping a jq program, so a placeholder there needs `'\''`: writing `'{{PLUGIN_ROOT}}/…'` silently TERMINATED and restarted the shell string — `bash -n` passed, the hook ran, the render looked right, and the single quotes had simply vanished from the emitted command. Only an end-to-end cell that re-reads the rendered line catches that, which is the reason to distrust a clean hand-edit. A static asset cannot be substituted at all, so `assets/design-seed/ADOPT.md` identifies the seed by `SEED_DIR` — the directory the reader opened it from, the one thing it provably holds — and `docs/design-seed-method.md` references its sibling as `../assets/design-seed/`, resolved from the doc.

- **A test that drives `session-start-hook.sh` must set `_SKILL_TEST_MODE=1`, and a hint renders only when a skill is SELECTED.** The hook REGENERATES the tracked `config/fallback-registry.json` from `config/default-triggers.json`, so a test that drives it with `CLAUDE_PLUGIN_ROOT` = the checkout rewrites a git-tracked file, and a restore after a mutation can drop a real edit (this is also why `done-gates.yml` forbids a working-tree cleanliness step, citing `test-registry.sh`). `_SKILL_TEST_MODE=1` is the hook's own suppression and does not affect cache building. `_format_output` takes the zero-match branch at `TOTAL_COUNT` 0 and emits no hints, and the fallback registry marks every skill `available: false`, so it can never render one — its copy of a hint is held to the default-triggers copy by an equality cell instead. A prompt that selects nothing (a bare "design the admin ui") renders nothing, which looks exactly like a broken hint. Regression for the design-seed hint: `tests/test-design-seed-hint-reachable.sh` renders it through the REAL hook from an external repo and opens every absolute path it names with `CLAUDE_PLUGIN_ROOT` unset, with the red control that the pre-fix paths are unopenable there, a >=2-path floor so a hint that dropped its paths cannot pass by checking nothing, and a lint over every hint in both configs with a population floor.

- **`assets/design-seed/ADOPT.md` ships a block the reader PASTES, so every destructive statement carries its own guard ON THAT LINE.** Turning a literal placeholder into a variable adds an expansion failure mode that did not exist: an unresolvable placeholder (`<plugin>`) is inert, a resolvable one is live, and `cp -R "${SEED_DIR}/." design/` with `SEED_DIR` unset is `cp -R "/." design/` — measured, **123 GB of the filesystem root** copied into a temp dir before the run was killed. Check that whenever a placeholder becomes a variable. The realistic trigger is an agent **pasting only the copy line**, so a guard rides ON THE DANGEROUS LINE and NOT on the neighbouring assignment a selective paste leaves behind, and that line stays ONE self-contained line (no `\` continuation): it is the unit a reader pastes AND the unit the test can execute. **ONE guard does not close a class**; the copy line carries three, each closing a measured hole: `${SEED_DIR:?…}` (`:?` catches EMPTY as well as unset, and fires before `cp` is reached in both shells); an identity check that the directory IS the seed, with TWO markers (`tokens.css` AND `checks/token-lint.sh`), because `:?` does not see `/`, `$HOME` or the plugin root, `-n` prevents OVERWRITING but not TRAVERSING, and `tokens.css` alone is a plausible file in any design-system repo; and `cp -Rn`, so a reader's existing files win (it fails SAFE: a `cp` without `-n` support errors rather than clobbering). **A guard against an ABSENT value does not constrain a WRONG value, and for a recursive command the wrong value is the expensive one.** A check that runs after the copy — step 3 running the adopted lint — is a detector, not a guard: "we notice once your home directory has been copied" is not a control. Guard each later statement against the earlier guards' effects: remove the seed's `ADOPT.md` only when `cmp -s` proves it is the seed's copy (`-n` preserves a reader's own, and an unconditional `rm` then deleted it — one guard protecting a file the next line destroys), and write `design/adopted.json` only when it is absent. Making a file reachable puts its latent hazards in scope: the clobber shape predated the hint fix and became live only once `ADOPT.md` could be found. Keep the one-line advisory before the copy: a skipping `cp -Rn` exits **1 with empty stdout AND stderr** (measured), and the natural reading of "adoption failed" is `rm -rf design`, destroying exactly what `-n` saved — **a guard whose failure mode invites the destruction it prevents is worse than no guard.** **UNVERIFIED and deliberately not claimed:** `-n` is not POSIX, and whether GNU `cp` returns 0 where BSD returns 1 on a skip is unmeasured — that would remove the only signal a skipping adoption gives on Linux. The doc's discovery command (`ls -dt ~/.claude/plugins/cache/*/…`) covers the marketplace layout ONLY and prints nothing for a `--plugin-dir` or checkout install; that is fixed in PROSE, deliberately not as a cell, because a cell asserting that glob passes here and fails in CI, which is a flaky test rather than a check.

- **`tests/test-design-seed-hint-reachable.sh` holds those guards, and each rule about its shape replaced a cell that passed with the defect present.** Assert a destructive guard through a recording **`cp` SHIM on `PATH`** that copies nothing, with a positive control proving the shim intercepts: running the unguarded form for real is the disaster the cell exists to prevent, so a regression must be OBSERVABLE without being destructive, and for a traversal target the property is that `cp` is NEVER REACHED, which is stronger than any claim about what `cp` produced. Pair every rejecting cell with an accepting control — the real seed is still accepted, the seed's own `ADOPT.md` is still removed, files the reader lacked still land — or a guard that rejects everything, or a copy that never ran, passes it. **Applying a fix is not demonstrating it is held: run the revert** (reverting the second marker once failed zero cells, because no fixture had a coincidental `tokens.css`). The copy-line anchor embeds the guards under test, so deleting a guard empties the extracted line and `sh -c ""` reaches no `cp`, which every "never reached" cell reads as success: check the extraction is non-empty BEFORE the cells that depend on it, and `_record_fail` + `continue` inside each loop so a skipped cell reports rather than vanishes — an assertion satisfied by the FALLBACK path pins nothing. **Execute the whole block, never hand-picked lines:** when a document ships a MULTI-STATEMENT procedure, an anchor list is a claim that you enumerated the statements, and that claim rots the moment one is added. The test extracts the whole fence and runs it twice per shell (a fresh tree, and one where the reader already owns every file), with a statement-count floor, a control that the script still RAN, and an assertion that the block's `design/` writes include the ones the cells cover; the fence is checked by IDENTITY (it must contain the copy), because `awk` takes the FIRST bash fence and `ADOPT.md` has a second. **Do not reintroduce an enumeration in this test** — a blocklist of destructive verbs, a list of named survival files and a `cd`-spelling check were each escaped in review, because an enumeration of command shapes is never provably complete (the `_gc_seg_is_inert` whitelist precedent). What holds instead: a ratchet on the COUNTS (`ADOPT_DESIGN_STMTS`, statements touching `design/`, and `ADOPT_BLOCK_LINES`, non-comment lines including the heredoc body — a change detector is named for what it counts, not for what would sound more rigorous), so adding a statement fails until its author covers it and bumps the number; a whole-tree snapshot (`find . -type f -exec cksum {} + | LC_ALL=C sort`) taken before the run, requiring every pre-existing line to survive byte-identical, ONE-DIRECTIONAL so adoption may still add files, with files seeded outside `design/` because a statement can reach anywhere; and CONTAINMENT, by launching inside a wrapper whose siblings are in the snapshot, so a relocation fails without naming any spelling. Residual, documented: a write to an ABSOLUTE path outside the wrapper needs a sandbox rather than a check. **Verify a limitation before writing it down:** `find -type f` uses lstat, so a file replaced by a symlink (even to identical content), a directory, a FIFO or a device node fails the comparison, and `chmod 000` is caught because `cksum` then fails; the only real blind spot is a readability-PRESERVING mode or ownership change (`chmod +x`, `chown`), deliberately not closed with a mode column because such a statement must appear in the block where the count ratchet sees it. A false known-limit invites someone to close a non-problem and to distrust the adjacent claim that IS real. Writing a spec BROADER than the fix is the same defect as leaving one narrower, and both are found by asking which sentences the code actually satisfies.
