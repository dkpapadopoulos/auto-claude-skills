# Push gate: shadow corpora and diagnostics

Path-scoped rule, split out of the repo-root `CLAUDE.md` Gotchas section so it
loads only when you touch the files it governs. History moved out of these bullets, with
the test, if any, that now guards it, is in `docs/history/rules-push-gate-telemetry.md` (loaded by nothing).

- Push-gate **diagnostic capture** (`scripts/push-gate-capture.sh`, issue #127) instruments `openspec-guard.sh` to catch the intermittent live-deny-while-replay-allows defect (`[[project_push_gate_unexplained_live_deny]]`, 2 hand-diagnosed occurrences; the instrument itself produced NO valid evidence until the classifier fix below, so do not re-inherit a "drift confirmed" reading from any pre-fix record). It runs ONLY from the guard's hardened EXIT trap as a **subprocess** — never `source`d on the decision path (a source-time Bash 3.2 error would trip the fail-open `trap 'exit 0' ERR` and skip enforcement; this was Codex P0). The trap does `trap - ERR; trap - EXIT; ( exec </dev/null >/dev/null 2>&1 … )` so it can never re-fire the ERR trap or leak a byte to stdout (the one-JSON-object contract). The guard's inline footprint is only a `_DECISION` var (default `allow`, set to `deny:<gate>` before each of the 7 deny `exit 0`) + the trap. Writes one compact JSONL record per push/merge to `~/.claude/.push-gate-invocation-log` (`0600` secured BEFORE first write, rotated to last 500). Raw command text is **NOT logged by default** (shell text can't be robustly de-secreted) — only `command_sha`+`command_len`+a coarse `command_label`; full best-effort-redacted text is opt-in via `PUSH_GATE_CAPTURE_FULL_CMD=1`. On a deny it runs a **true on-disk replay** (`PUSH_GATE_CAPTURE_DISABLE=1` recursion guard) and classifies it POSITIVELY as `ondisk_replay_decision` = `deny`/`allow`/`incomplete` — because the replayed guard is itself fail-open, it prints a `__PGC_EVALUATED__` sentinel (under `PUSH_GATE_CAPTURE_REPLAY=1`, never live) so an empty replay ≠ a genuine allow. `deny`+`allow` ⇒ live≠on-disk ⇒ **drift confirmed**; absence of any record for a live-denied push ⇒ the on-disk guard never ran ⇒ stale in-process/cached code (`guard_cksum`/`capture_error` disambiguate). Diagnostic-only → deliberately **EXCLUDED** from `_GATE_ENFORCE_LIBS`. **The replay classifier MUST match BOTH JSON forms:** the guard emits deny JSON via `jq -n`, which PRETTY-prints (`"permissionDecision": "deny"` — space after the colon, own line), while its advisory paths emit compact `printf` JSON. A compact-only needle silently classified **every** live deny as `allow` = "drift confirmed", so deny records logged before the fix carry **zero information**, and they are NOT retro-classifiable (the JSONL deliberately omits `PGC_INPUT`, so no archived record can be replayed). The classifier matches both literal forms in one `case`; do NOT "simplify" it to `${_rout//[[:space:]]/}` — bash 3.2 bracket-class substitution is ~O(n^2.7) (110ms at 1KB, 24.5s at 8KB) and this runs synchronously in the guard's EXIT trap. Deny must be tested before the sentinel branch (the sentinel precedes every deny site, so a deny replay contains both). Any test of an output classifier MUST derive its fixture from the real producer (`tests/test-push-gate-capture.sh` greps the guard's actual emitter line) and assert the field end-to-end against the REAL guard, not only against stubs: a stub that hand-writes the producer's output proves only that the classifier agrees with the test's own idea of that output. Regression: `tests/test-push-gate-capture.sh`.

- **The REVIEW shadow corpus's first pre-registered window is CLOSED as a NULL RESULT, and its records are NOT poolable (#239).** `hooks/lib/review-shadow.sh` has appended a record per would-block since 2026-08-26, but **no reader existed** — `scripts/shadow-adjudicate.sh` is IMPLEMENT-only — so the pre-registration in `openspec/changes/review-verdict/design.md` reached its **n=29 floor on 2026-09-03 and nobody could see it**, with **0 adjudications**. **A pre-registration with no instrument reaches its floor silently and stays advisory by inertia** — build the reader WITH the writer. **DECIDED 2026-09-23 — the window is CLOSED as a NULL RESULT** on the ground that it was never instrumented (owner ruling; the recommended route, rather than a choice between the `n` readings). The deny-flip is NOT authorised and the leg stays advisory **by decision, not default**; the backstop, the horizon and the 2026-10-27 override deadline are all SPENT with the window; the 199 records stay descriptive-only. A successor window is deliberately NOT registered here — registering one is a separate act. The full record is "DECIDED 2026-09-23" in that `design.md`. **Zero adjudications is not zero false blocks, it is no measurement.** The floor, bands, episode definition and `false_block` definition are NOT open. **Three things a successor must fix:** name `n` unambiguously (one sense, no clause relying on the other — this registration's floor needed ADJUDICATED episodes while its backstop and horizon were accrual arguments needing RECORDED ones, and the two senses disagreed about whether a deadline bound); NAME THE ADJUDICATOR AND CADENCE (every safeguard here guarded accrual, and the corpus accrued 17x fast and stalled on human labelling nobody scheduled); and SHIP THE READER WITH THE WRITER. Do not assert one reading of an ambiguous registration while shipping the other, and do not choose between readings after seeing the data: resolving a pre-registration's ambiguity after seeing the data is the discretion it exists to refuse. **The corpus is unpoolable for a reason predating all of this:** `78aa21e` (#219, 2026-09-01) moved THIS leg's own fire condition (`_diff_touches_material_source`, `review_verdict_covers_head`) onto the resolved subject, bumped `implement-shadow.sh`, and **left `review-shadow.sh` untouched** — so all 199 records say `predicate_version 1` while spanning two fire conditions, and a timestamp cannot recover which guard wrote one (sessions run cached plugin versions). **`predicate_version 2` has TWO independent grounds** — `78aa21e`'s fire-condition change, AND the recorder fix itself, because `repo`/`branch` ARE the episode key and `head_sha` is the adjudicator's anchor, so a session-derived branch can split one real episode into two (inflating n toward the floor) or send an adjudicator to the wrong branch's history. Recording only the first ground would invite re-pooling the old corpus later. **The stated rule "fire condition ⇒ predicate, describes ⇒ schema" HAS A GAP:** the test is whether the change alters what a pooled EPISODE DENOMINATOR or a pooled true_catch/false_block LABEL means, not whether the leg fires differently — read it literally and you reach the wrong answer here in good faith. `schema_version 2` is the recorder fix: the record now names the SUBJECT (`_SUBJ_ROOT`/`_SUBJ_REV`, which every predicate the leg fires on already took), not the session's `_proot`. PAIRED: `scripts/review-shadow-adjudicate.sh` (diagnostic-only, excluded from `_GATE_ENFORCE_LIBS`) reports the excluded band **with its cause** — silently counting those records and silently dropping them are the same error facing opposite ways — and DESCRIBES it (episodes/span/accrual, labelled never-poolable) so the amendment's figures are reproducible BY THE INSTRUMENT; a legacy record has no `record_id`, so a line-ordinal stands in, which is safe ONLY because nothing is ever stored against it. `hooks/lib/shadow-corpus.sh` single-sources the band rule, the ISO→epoch prelude and episode grouping across BOTH legs; a new leg MUST use it rather than re-derive. **Reader rules — each was a measured defect that could certify the flip on bad evidence or hide a record:** count diversity over the same human-confirmed episodes the rate counts, never over every episode; key diversity by REPOSITORY (origin URL → `--git-common-dir` → path, the `branch_ledger_key` precedent), never by worktree path (`--show-toplevel` gave 15 distinct values for 5 repositories); read every JSONL file with `-R fromjson?`, because jq ABORTS on the first malformed line and returns what it parsed before, so a bad line at row 29 of 35 drops a later `false_block` while `n>=29` survives ⇒ **k falls and the band CLEARS**; keep an AGENT-claimed verdict out of the human-confirmed `k`; filter `would_block == true` in this reader's `_episodes` as its `--next` does (the IMPLEMENT reader below filters outside its shared `_episodes()` instead); never let "no records" and "none countable" collapse into one message (`ts:""` is producer-reachable when `date` fails), and report a record that parses but has an unusable `ts` rather than dropping it; report an unreadable corpus as unreadable, never as empty (`-f` is not `-r`, and a count pipeline ending in `tr` discards the read error); group with `LC_ALL=C sort` (a non-C collation can order two byte-different keys adjacently while awk compares `!=`, splitting an episode and INFLATING the denominator); and `shadow_band` ERRORS on absent `ALPHA`/`DENY_P`/`ADVISORY_P` rather than defaulting — a band computed from probabilities nobody chose is worse than no band. **Test rules — each cell below was vacuous until a mutation or a review said so:** cross-check pre-registered constants against `design.md` as a SECOND authority plus hardcoded literals as a third, with a **floor on the number of constants matched** so a reworded doc cannot make the greps silently match nothing, and never let a band cell set `ALPHA`/`DENY_P`/`ADVISORY_P` itself (every constant could then be relaxed with a fully green suite); make some fixture REACH every branch (`FLOOR_REPOS` sat behind an `elif` no fixture reached); prove version derivation by MOVING the producer, not reading it (the no-lib fallback literal equalled the producer constant); assert that an empty-branch episode reaches the RATE, never just that it was counted (the tab-IFS collapse shifts COLUMNS, so the row is still counted while its episode leaves the DENOMINATOR); a mutation that changes nothing, such as `| head -1` on an awk that already prints one line, is not evidence of a vacuous cell; for a subject fix, assert the field only the ROOT determines (`.repo`), because the subject worktree and the session checkout share refs and objects, so the REV alone supplies the right `branch`+`head_sha` whichever root is passed — 8b certified the regression it names until it read `.repo`; match a static call's ARGUMENT POSITION, never a substring of a neighbourhood a comment can satisfy; and keep one round-trip cell calling the real `review_shadow_record` then the real reader, because fixtures that retype the field names leave a writer-side rename green in both files. Regression: `tests/test-review-shadow-adjudicate.sh`, `tests/test-review-verdict.sh` (8b/8c).

- `scripts/shadow-adjudicate.sh` (Stage C2) labels IMPLEMENT shadow records and reports the pre-registered rate. **Diagnostic-only** — never sourced by the guard, deliberately EXCLUDED from `_GATE_ENFORCE_LIBS`, emits no `permissionDecision`, writes no gate state (all pinned by `tests/test-shadow-adjudicate.sh`). Adjudications append to a SIDECAR (`~/.claude/.push-implement-adjudication.jsonl`, `IMPLEMENT_ADJUDICATION_LOG` overrides); the C1 shadow log is NEVER mutated. Four rules are easy to break: (1) the denominator is independent **episodes**, not records — `(repo, branch, session_token)` within 30 min **anchored at the episode's FIRST record**, not a rolling gap (a rolling gap chains a whole day into one episode); (2) bands are **exact Clopper–Pearson**, computed as a direct CDF comparison (`DENY ⟺ P(X≤k|n,0.10)<0.05`, `ADVISORY-ONLY ⟺ P(X≥k|n,0.20)≤0.05`) — Wilson is anti-conservative and calls 8/23 advisory where exact says narrowed, which is a pinned test; (3) agent-claimed adjudications are EXCLUDED from the rate until a human re-confirms, because this leg governs agent pushes and the subject has an incentive to self-grade; (4) claimant detection uses `CLAUDECODE` + `CLAUDE_CODE_SESSION_ID` (the repo's established marker) — a tty check was specified and REMOVED, because `[ ! -t 1 ]` fires on any redirect or pipe, and since human-claimed episodes are the only countable ones that silently makes the n=29 floor unreachable rather than costing a re-confirmation. The `claude`-parent check is INERT in this harness (Bash calls run under an intermediate shell, so `claude` is the grandparent); walking more ancestors was tried and REVERTED because inside a session every ancestry contains `claude`, making the human path untestable. Episode verdicts resolve **worst-verdict-wins** (any `false_block` wins) with the LATEST adjudication per record superseding earlier ones — folding over all rows made a correction a silent no-op. **THREE `IFS=$'\t' read` traps were removed** — tab is IFS *whitespace*, so an empty field (e.g. the empty `branch` `implement-shadow.sh` writes when `rev-parse --abbrev-ref` fails) collapses and shifts every later column. In `_episodes` and `cmd_next` that dropped the record from the denominator / blanked the transcript pointer, fixed by splitting in `awk -F'\t'`. In `cmd_status` the loop must stay in the current shell (heredoc, so the counters survive), so it re-splits on **`\x1f`** via `tr '\t' '\037'` — `\x1f` is not IFS whitespace, so empty fields survive. PAIRED: never re-split tab-delimited data with bash `read`; use `awk -F'\t'`, or `tr` to `\x1f` when the loop body must mutate shell state. Floor binds on the rate's denominator, not the labelled count. **(5) The rate population is `would_block == true` ONLY** — attested non-blocks cannot contain a false block by construction, so the rate must not pool them and `--next` must not queue them. Dilution here biases toward CLEARING the deny-flip — the unsafe direction. The filter is deliberately NOT inside `_episodes()` (shared; filtering there erases the attested population #169 exists to make visible), membership is read from the boolean and NEVER inferred from `impl_evidence_kind` (format-frozen, describes evidence not membership, and correlates only incidentally), and the **diversity floor moved too** — otherwise attestation episodes satisfy >=2 repos with zero false-block evidence spanning repos. Mixed episodes are classified by **ANY record would have blocked**, chosen because `_episodes()` anchors on the earliest record so an anchor-reading rule would classify by arrival order; both orders are pinned. A missing/non-boolean `would_block` is REPORTED as excluded, never coerced to false. No `predicate_version`/`schema_version` bump: this is a reader fix, the records and the firing predicate are unchanged. Regression: `tests/test-shadow-adjudicate.sh`.

- **REVIEW predicate 3, push-time stamps and `--evidence-miss` (openspec `review-credit-from-evidence`).** `REVIEW_SHADOW_PREDICATE_VERSION` is **3** because typed-slash, equivalent-skill and returned-reviewer credit widen `_review_completed`, the leg's population — the pooled-episode test above, not "the fire condition changed". Predicate-2 records must not be pooled; `--status` now reports them as other-predicate. `IMPLEMENT_SHADOW_PREDICATE_VERSION` is **6** on the same test: `subagent-driven-development` and `agent-team-execution` are credited REVIEW names AND IMPLEMENT-slot names, so a typed one now satisfies the IMPLEMENT leg and a push that was a would-block record is none; v5 is never pooled with v6 (`shadow-adjudicate.sh` derives the version from the producer). The VERIFY predicate (2) is unchanged. All three records gain `session_id`, `tool_use_id` (the push call's), `cc_version` (`acs_cc_version` from `AI_AGENT`, no fork, `""` when absent) and `acs_version`, as a schema bump (REVIEW 3, IMPLEMENT 5, VERIFY 3), filled by the guard's `_shadow_stamp_prepare` only when a record is about to be written (one jq plus one subshell per run); a value failing validation is stored as `""` and never drops the record. REVIEW records also carry `review_witness` (`reviewer-returned` > `verdict` > `invocation` > `none`) and `review_coverage` (`covered|uncovered|cannot-check|none`), computed by `_review_witness`, which never calls the predicates that append advisories. `scripts/review-shadow-adjudicate.sh --evidence-miss` counts an episode as a miss only for a would-block predicate-3 record with `reviewer-returned` + `covered`, and reports every other record as excluded with its cause. **It is a lower bound on one kind of false block, NOT the registered false-block rate**: invocations never count (#197); a reviewer whose dispatch sha was `-` is recorded under another witness and never counts; and the last-writer-wins `reviewer-returned` milestone can hide an earlier covering reviewer. The reader's fallback predicate literal is pinned to the producer constant. Regression: `tests/test-review-witness.sh`, `tests/test-review-shadow-adjudicate.sh`, `tests/test-push-gate-implement-leg.sh`, `tests/test-verify-measured-verdict.sh`.
